{{- if .Values.browserPool.enabled }}

The browser pool is experimental. Browser checks run on crocochrome instead of a local Chromium.
It requires an agent image with the -browser-pool-* flags; older images exit on startup. Refer to the chart README.
crocochrome: Deployment {{ include "sm-agent.crocochromeName" . }}{{ if not (kindIs "invalid" .Values.browserPool.crocochrome.replicas) }}, {{ .Values.browserPool.crocochrome.replicas }} instances{{ end }}, one browser session per instance.

{{- if .Values.browserPool.crocochrome.unprivileged }}

crocochrome uses the unprivileged image, which meets the Pod Security "restricted" profile. Chromium runs as the
same user as crocochrome, so it isn't isolated from it. Use it only if you trust the check scripts and the pages they load.
{{- else }}

crocochrome requires allowPrivilegeEscalation and the SETUID, SETGID, KILL, CHOWN, DAC_OVERRIDE, and FOWNER
capabilities. It meets the Pod Security "baseline" profile, but not "restricted". To meet "restricted", set
browserPool.crocochrome.unprivileged, which trades away Chromium's isolation from crocochrome. Refer to the chart README.
{{- end }}
{{- if not .Values.browserPool.crocochrome.networkPolicy.enabled }}

WARNING: browserPool.crocochrome.networkPolicy.enabled is false. The crocochrome API doesn't have authentication:
anything that can reach port 8080 can start browser sessions in your network.
{{- end }}
{{- if and .Values.browserPool.crocochrome.networkPolicy.enabled (not .Values.browserPool.crocochrome.networkPolicy.extraIngressFrom) }}

NOTE: the crocochrome NetworkPolicy only allows the agents. To scrape crocochrome metrics, with the ServiceMonitor or
any other scraper, add the scraper's Pods to browserPool.crocochrome.networkPolicy.extraIngressFrom.
{{- end }}

NOTE: image.variant is browser, but the browser pool doesn't need Chromium in the agent image.

{{- end }}
